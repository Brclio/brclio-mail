# 已知限制与路线图

## 发布级别

当前仓库是 **Preview**，目标是可验证的单节点功能原型，而不是“完整、成熟、生产级邮箱”。没有可用性 SLA、兼容性承诺、独立安全审计或无损升级保证。

## 明确限制

- 仅支持单主机、单进程副本、本地 SQLite；不支持 NFS/SMB、共享数据库、多副本、高可用或自动故障转移。
- 管理员归档不是 WORM；主机 operator 能修改/删除数据库和审计日志。
- 管理员可读取所有已收发或非草稿导入的邮件，包括用户已删除邮件，属于显著隐私能力；尚未发送的私有草稿不进入管理员归档。
- 入站没有 SPF、DKIM、DMARC 验证，也没有反垃圾、DNSBL、灰名单、杀毒或附件沙箱。
- 没有 MTA-STS 策略托管/执行、DANE、S/MIME、OpenPGP 或端到端加密。
- 直接 MX 投递是实验功能，默认关闭；推荐 smarthost。
- 没有完整退信/DSN 分类、投诉反馈回路、信誉预热和投递率分析。
- 没有内置 MFA/SSO、细粒度管理员角色、不可篡改外部审计或数据导出审批流。
- 认证限速是单进程内存状态，重启会清零；没有完整连接级 DoS 防护。
- 用户 quota 只约束当前可见邮箱副本，不是每租户的永久归档预算；受信任账号可以通过反复写入再 EXPUNGE 消耗全局归档 cap。Preview 只适合完全受信任的账号，必须监控归档增长并及时停用异常账号。
- 没有 Prometheus/OpenTelemetry 指标、自动告警、DMARC/TLS-RPT 解析或内置 SIEM 集成。
- 数据库和备份没有应用层加密；依赖宿主机和备份系统保护。
- 没有 POP3、JMAP、ActiveSync、CalDAV/CardDAV、Sieve、共享邮箱、日历/联系人。
- API、数据库 schema、UI 和客户端兼容性仍可能在 Preview 更新中变化。

## 生产化优先级

### P0：公开生产前

- 入站 SPF/DKIM/DMARC 验证与 Authentication-Results；
- 成熟反垃圾/恶意软件扫描、隔离区、管理员误判处理和更新机制；
- SMTP/IMAP/Web 连接级滥用保护、持久限速、可观测性与告警；
- 完整 DSN/bounce、退信分类、投诉和 suppression 流程；
- 独立安全审计、模糊测试、协议互操作矩阵和长期压力测试；
- 签名发布、SBOM、依赖与容器扫描、可验证的发布流程；
- 明确的数据保留、用户告知、管理员访问审批及外部只追加审计；
- 自动化恢复测试、版本化迁移/回滚策略和公开兼容政策。

### P1：邮件生态完整性

- MTA-STS 策略托管与出站执行、TLS-RPT 报告解析；
- DKIM selector 轮换、密钥吊销/迁移工具；
- 更完善的队列管理、重试/暂停/重投控制和送达诊断；
- per-domain 限速、连接池、信誉与 smarthost failover；
- RFC 互操作测试、特殊 MIME/国际化地址策略和客户端矩阵；
- MFA/WebAuthn、管理员角色分离和敏感归档双人审批。

### P2：产品能力

- 邮件规则/Sieve、共享邮箱、自动回复、转发安全策略；
- 标准化自动配置、更多客户端协议与导入/导出；
- 可访问性、本地化、搜索和大邮箱性能优化；
- 可选的外部对象存储/搜索后端，但必须先重新设计一致性、加密与备份边界。

## 不应被路线图暗示的承诺

SQLite 单节点是当前架构边界。即使未来研究高可用，也不能通过把当前 WAL 数据库放到 NFS 或简单增加副本实现。任何多节点方案都需要新的存储、一致性和故障模型，并单独发布成熟度声明。

路线图是方向，不是交付日期或兼容承诺。需要生产级邮件基础设施时，应选择经过长期运维验证、具有成熟反垃圾与升级路径的现有方案，而不是等待本 Preview 承担关键业务。
